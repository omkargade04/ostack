# Maintain a verification skill

Adapted from pstack `maintain-verification-skill` (MIT). A feature map rots the moment the app changes. This is the upkeep loop for a skill generated by `/create-verification-skill`. The unit of rigor is the feature, not every sentence: cover every feature file from source and exercise every feature live.

## Outcomes

Pick one, and say which:

- **clean:** every feature got source and live coverage. Nothing to change.
- **changed:** proven corrections to the verify skill's docs, harness, or map. A commit or PR only when the user's message asks for one.
- **blocked:** coverage could not finish, or a proven fix could not land safely. Say exactly what blocked it.

## Edit scope

Edit only the verify skill's own directory (`~/Desktop/Work/ostack/skills/verify-<app>/`: its SKILL.md, `features/`, and its scripts). Never edit product code. A behavior that the map describes and the app no longer does is either doc drift (fix the map) or a product regression (report it, do not paper over it in docs).

## Pass

0. **Locate the target.** Find the `verify-*` skill to maintain under `~/Desktop/Work/ostack/skills/`. Several candidates: ask which one. None: stop and point at `/create-verification-skill`.
1. **Index hygiene.** Read the feature map README and list its sibling files. Fix missing, extra, duplicate, or dead entries.
2. **Source wave.** One read-only `Agent` (`subagent_type: "Explore"`, Sonnet) per feature file, launched in one message. Each explains how the feature works from source, flags likely doc drift with citations, and returns one live recipe. They never drive the app and never edit files. Return shape: feature summary, source entry points, likely drift or none, one recipe.
3. **Reconcile.** Every feature file has a returned summary. Merge overlapping recipes into as few runs as practical. Spot-check cited drift. Sweep recent changes for user-facing features missing from the map, with a concrete source path before you call one missing.
4. **Live pass.** Required even when the source looks clean. It needs the user's go and an allowlisted tenant (the shared core's gate). This session owns all driving. Exercise every feature at least once, and hold three rules for the whole pass:
   1. Never drive a run that you have not checked with doctor since it last did something surprising.
   2. Evidence captured so far survives every cleanup. Check it at its named location.
   3. Nothing a drive started outlives its use. Replay the undo ledger after each failed drive.
   A doctor failure caused by drift in the skill is drift: fix it under the edit scope and retry once before you call the pass blocked. A feature that cannot be reached is `verified-unreachable` only with the concrete missing prerequisite and the route you tried.
5. **Triage.** Wrong or missing user-POV description: doc drift, fix it. Working behavior that the harness cannot drive: harness gap, fix it. App behavior that is broken: product gap, record it for the user, keep it out of the verify skill changes.
6. **Report.** Re-read every changed file. Report the outcome, the features covered, unreachable prerequisites, confirmed drift, and product gaps. Write the run notes to the effort dir.
